# 全局异常与 I18n 规范 (Lite)

## 1. 核心契约 (Core Principles)
* **零硬编码**: 严禁在代码中直接写错误字符串，必须通过 `ApiError` 注册。
* **映射一致**: `messages_*.properties` 的 Key 必须与 `ApiError` 枚举变量名完全一致。
* **占位符**: 统一使用 `{0}`, `{1}`。严禁使用 `%s` 或 `{}`。

## 2. 错误码区间划分
| 业务域 | 前缀示例 | 区间范围 | 说明 |
| :--- | :--- | :--- | :--- |
| **系统基础区** | `HTTP_`, `COMMON_`, `QUERY_` | 0 - 1999 | 网关、参数校验、通用错误 |
| **业务逻辑区** | `AUTH_`, `WH_`, `PO_`, `FIN_` 等 | 2000 - 99999 | 各模块具体业务异常 |

## 3. 命名与格式
* **枚举命名**: 采用 `DOMAIN_ACTION_RESULT` 格式（如 `WH_STOCK_NOT_ENOUGH`）。
* **Code 命名**: 除非特殊指定，关联的 code 字符串必须采用 **camelCase (驼峰命名)**。
* **抛出规范**: 仅允许抛出 `ServiceException`，推荐使用 `BizAssert` 工具类。

## 4. 维护红线 (🚨 Redlines)
* **稳定至上**: 🚨 **严禁修改或调整已有的错误码** ID、变量名或核心语义。
* **优先复用**: 新增前必须全量检索 `ApiError.java`。语义相同者必须直接复用。
* **就近插入**: 新错误码必须插入在相关业务块下方，严禁堆在文件末尾。
* **去重防线**: 生成数据前**必须强制检查**重复。发现重复时，**严禁自动覆盖**，必须暂停并提示用户决策。
